# Incident Investigation: Multiple Failed Windows Logons

## Incident Overview

This investigation documents a Microsoft Sentinel security incident generated after multiple failed Windows authentication attempts were detected against a Windows Server endpoint in a controlled SOC lab environment.

The incident was generated by a custom Microsoft Sentinel detection rule designed to identify three or more failed Windows logon attempts associated with the same account, computer, and source IP address within a 10-minute period.

The activity was intentionally generated for security testing and was investigated using Microsoft Sentinel, Windows Security events, and Kusto Query Language (KQL).

---

## Environment

- SIEM: Microsoft Sentinel
- Log source: Windows Security Events
- Endpoint: Azure-hosted Windows Server virtual machine
- Log Analytics workspace: `law-sentinel-lab`
- Primary account investigated: `labadmin`
- Relevant Windows Event IDs:
  - 4624 - Successful account logon
  - 4625 - Failed account logon
  - 4688 - New process created

---

## Detection

A custom Microsoft Sentinel analytics rule was created to identify repeated Windows authentication failures.

### Detection Logic

The rule analyzes Windows Security Event ID 4625 and groups failed authentication events by:

- Computer
- Account
- Account domain
- Account name
- Source IP address

An alert is generated when three or more failed authentication attempts meet the detection criteria.

The rule was configured with:

- Severity: Medium
- Query frequency: 10 minutes
- Lookback period: 10 minutes
- Threshold: 3 or more failed logons

### MITRE ATT&CK Mapping

The detection was mapped to:

- **TA0006 - Credential Access**
- **T1110 - Brute Force**
- **T1110.001 - Password Guessing**

---

## Alert and Incident Generation

The controlled authentication failures successfully triggered the custom detection rule.

Microsoft Sentinel generated an incident titled:

**Multiple Failed Windows Logons**

The incident correlated the following entities:

- Windows endpoint
- User account
- Source IP address

This demonstrated how entity mapping can provide context for an analyst investigating authentication-related activity.

---

## Authentication Investigation

KQL was used to examine both failed and successful Windows authentication events associated with the account.

The investigation identified:

- Event ID 4625 failed authentication attempts.
- Event ID 4624 successful authentication events.
- Multiple failed logons occurred within a short period.
- Successful authentication activity was also present around the authentication testing period.

Reviewing both failed and successful authentication events provided additional context beyond the original alert.

---

## Process Investigation

Windows Event ID 4688 was analyzed to review processes created on the endpoint around the authentication activity.

The process investigation examined:

- Process name
- Parent process
- Account
- Command-line information when available
- Event timestamp

Additional KQL aggregation was performed to summarize process execution frequency and identify parent-child process relationships.

Observed processes were consistent with expected Windows session activity in the lab environment, and the investigation did not identify evidence of unexpected process execution associated with the simulated failed-logon activity.

---

## Investigation Conclusion

The Microsoft Sentinel alert successfully identified the intentionally generated authentication failures.

After reviewing the authentication timeline, associated entities, successful and failed logons, and Windows process creation activity, the incident was determined to be expected activity generated as part of the controlled security lab.

The incident was resolved in Microsoft Sentinel with the classification:

**Informational, expected activity - Security testing**

No remediation action was required.
